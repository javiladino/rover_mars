[![Lint](https://img.shields.io/badge/lint-ruff-informational)](.github/workflows/lint.yml)
[![Tests](https://img.shields.io/badge/tests-pytest-informational)](.github/workflows/test.yml)

[![License: MIT](https://img.shields.io/badge/license-MIT-lightgrey)](LICENSE)

**Simulation of the complete NASA Mars 2020 / Perseverance Mastcam-Z data pipeline**, from image capture on the Martian surface to calibrated science products on Earth — built as a **Modern Data Stack** project: streaming (Kafka), Medallion architecture, orchestration (Airflow), declarative transformation (dbt), data quality, CI/CD, and AWS integration.

> This project replicates the exact data flow and methodology used by NASA's Jet Propulsion Laboratory (JPL) and the Multi-mission Image Processing Laboratory (MIPL) to process images from the Mastcam-Z stereo cameras aboard the Perseverance rover at Jezero Crater, Mars.

📄 **Architecture documentation:** [docs/ANALISIS_MODERN_DATA_STACK.md](docs/ANALISIS_MODERN_DATA_STACK.md) (ADRs, ES) · [docs/GUIA_IMPLEMENTACION_MODERN_DATA_STACK.md](docs/GUIA_IMPLEMENTACION_MODERN_DATA_STACK.md) (step-by-step guide, Phases 1-6, ES)

## Results — Live System

The diagram above is the promise; this is the proof that the system runs end to end, with data generated by the simulator itself, flowing through Kafka, Airflow, dbt, and Postgres into a real dashboard.

![Demo: Mars-to-Earth data flow and the interactive data-flow map](docs/images/demo.gif)

### Grafana — MEDA Telemetry & Mastcam-Z Coverage

![Grafana dashboard: temperature/pressure, diurnal curve, wind, image coverage, and detected anomalies](docs/images/grafana_dashboard.png)

5 panels built on real data generated by the pipeline, not sample data:

- **Diurnal temperature curve** (`lmst_h` on the X axis) — reproduces the sinusoidal shape of MEDA's physical model (minimum before dawn, maximum after Martian noon), not a sample line.
- **Temperature & pressure**, **Wind** — time series with a dedicated right-hand axis for the variable on a different scale, so one doesn't flatten the other.
- **Image coverage per sol** — the 5:3 ratio between left/right camera matches the simulator's actual capture plan exactly (wide stereo RGB, red zoom, NIR, atmospheric blue).
- **Detected anomalies** — rows automatically flagged by the rules in `meda_anomaly_rules.py` whenever a reading crosses the configured threshold, not a hand-curated table.

### Airflow — MEDA Pipeline Orchestration

![Airflow: meda_full_pipeline DAG graph](docs/images/airflow_dag_graph.png)

The `meda_full_pipeline` DAG implements Raw → Bronze (validation) → Silver (calibration + anomaly detection) → Gold (dbt aggregates), following the Medallion contract from the [project constitution](.specify/memory/constitution.md): every layer transforms, none is skipped.

## Mastcam-Z Camera Specifications

| Parameter | Value |
|-----------|-------|
| CCD format | 1648 × 1214 pixels |
| Pixel size | 7.4 µm × 7.4 µm |
| Bit depth | 12-bit (DN 0–4095) |
| Focal length | 26–110 mm (4:1 zoom) |
| FOV (wide) | 25.6° × 19.2° |
| FOV (tele) | 6.2° × 4.6° |
| Filter positions | 8 per camera (16 total) |
| Spectral range | 400–1012 nm |
| Stereo baseline | 24.3 cm (Left to Right) |
| Compression | ICER (lossy) / Lossless |
| APID Left | 0x01A5 |
| APID Right | 0x01A6 |

### Filter Wheel Configuration

| Position | Left Camera | λ (nm) | Right Camera | λ (nm) |
|----------|-------------|--------|--------------|--------|
| 0 | L0 Broadband RGB | 530 | R0 Broadband RGB | 530 |
| 1 | L1 Blue | 445 | R1 NIR-480 | 480 |
| 2 | L2 Green | 527 | R2 Green | 530 |
| 3 | L3 Red | 676 | R3 Red | 630 |
| 4 | L4 NIR-800 | 800 | R4 NIR-800 | 800 |
| 5 | L5 NIR-866 | 866 | R5 NIR-908 | 908 |
| 6 | L6 NIR-910 | 910 | R6 NIR-937 | 937 |
| 7 | L7 NIR-939 | 939 | R7 SWIR-1012 | 1012 |

## Data Pipeline — Medallion Architecture

### RAW Layer (MinIO: `mastcamz-raw`)
- Binary `.IMG` files (12-bit CCD data, big-endian)
- PDS4 XML labels per image
- Immutable — never modified after arrival

### BRONZE Layer (MinIO: `mastcamz-bronze`)
- Validated and catalogued JSON metadata
- CRC-16/CCITT integrity verified
- DSN station stamped, light-delay recorded
- Indexed in PostgreSQL `image_products` table

### SILVER Layer (MinIO: `mastcamz-silver`)
- Radiometrically calibrated:
  - Bias subtraction (DN − 2047)
  - Dark current correction
  - Flat-field per filter
  - DN → I/F conversion
- Geometric calibration (CAHVOR camera model)
- Stereo disparity map (24.3 cm baseline)
- PostGIS image footprint polygon

### GOLD Layer (MinIO: `mastcamz-gold`)
- Sol-level aggregate statistics
- Multispectral composite summary
- Rover traverse GeoJSON path
- Dust storm event flags
- Grafana-ready time-series

## Airflow DAG Tasks

```
start_pipeline
    └── poll_bronze_queue         (Kafka consumer, up to 50 events)
         └── validate_raw_products (PDS4 + CRC check)
              └── radiometric_calibration (Bias/Dark/Flat/IOF)
                   └── geometric_calibration (CAHVOR model)
                        └── write_silver_layer (MinIO/S3 silver)
                             ├── update_postgis (image footprint upsert)
                             │        └── dbt_build (staging + marts + tests, see dbt/)
                             └── anomaly_detection (dust storms, alerts)
                                  └── build_gold_aggregates (sol stats)
                                       ├──────────────┐
                                       └── notify_science_team ← dbt_build
                                            └── end_pipeline
```

The calibration math (radiometric/geometric) lives in [airflow/plugins/calibration.py](airflow/plugins/calibration.py) — pure functions, covered by [tests/test_calibration.py](tests/test_calibration.py), independent of Airflow.

## Communication Chain (Simulated)

| Leg | Protocol | Data Rate | Delay |
|-----|----------|-----------|-------|
| Rover → MRO | UHF 437 MHz | ~2 Mbps | ~8 min/sol window |
| MRO → DSN | X-Band 8.4 GHz | up to 100 Mbps | 3–22 min (light time) |
| DSN → JPL | Fiber (TDRS) | 100+ Mbps | seconds |
| Kafka simulation | Local TCP | unlimited | configurable delay |

### DSN Ground Stations Simulated
- **Goldstone, California** — DSS-14 (70m), primary Mars link
- **Madrid, Spain** — DSS-63 (70m)
- **Canberra, Australia** — DSS-43 (70m)

### CCSDS Space Packet (CCSDS 133.0-B-2)
```
Primary Header (6 bytes):
  VER(3) | TYPE(1) | SHF(1) | APID(11) | SEQ_FLAGS(2) | SEQ_COUNT(14) | DATA_LEN(16)

Secondary Header (16 bytes, simulation):
  SCLK(8) | SOL(4) | WAVELENGTH_NM(2) | CRC16(2)
```

## Mars Environment Model

The telemetry generator replicates MEDA (Mars Environmental Dynamics Analyzer) measurements:

| Parameter | Range | Model |
|-----------|-------|-------|
| Surface temperature | −120 to +50 °C | Diurnal + seasonal |
| Air temperature (1m) | −120 to +30 °C | T_surface − 20°C |
| Atmospheric pressure | 600–850 Pa | Seasonal CO₂ cycle |
| Wind speed | 0–25 m/s | Gaussian + seasonal |
| Dust opacity τ | 0.3–8.0 | Storm probability model |
| UV index | 0–6 | Perihelion-scaled |
| MMRTG output | 110 → 95 W | 4.8%/year RTG decay |
| Light travel time | 3–22 min | Synodic orbit model |

## Quick Start

### Prerequisites
- Docker 24+ and Docker Compose v2
- Python 3.11+ (for standalone simulator)
- 8 GB RAM minimum (16 GB recommended)

### Deploy All Services

```bash
# Clone the repository
git clone https://github.com/javiladino/rover_mars
cd rover_mars

# Copy the env template and set your own credentials (.env is gitignored)
cp .env.example .env
# Generate a real Airflow Fernet key and paste it into .env:
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

# Launch all Docker services (equivalent to: make up)
docker compose up --build -d

# Monitor startup
docker compose ps
```

Full step-by-step guide (includes dbt, tests, CI/CD, and AWS deployment): [docs/GUIA_IMPLEMENTACION_MODERN_DATA_STACK.md](docs/GUIA_IMPLEMENTACION_MODERN_DATA_STACK.md) (ES)

Credentials: defined in your `.env` (see `.env.example`), never hardcoded in the repo.

```bash
cd simulator

SIMULATION_TOTAL_SOLS=20 \
```

### Useful Queries

```sql
-- Image coverage per sol
SELECT * FROM science.sol_filter_coverage;

-- Rover traverse path (GeoJSON)
SELECT sol, ST_AsGeoJSON(rover_location) FROM science.rover_traverse;

-- Dust storm events (τ > 2.0)
SELECT * FROM science.dust_storm_events;

-- Full telemetry time-series (Grafana source)
SELECT * FROM science.telemetry_timeseries WHERE time > NOW() - INTERVAL '7 days';
```

```
urn:nasa:pds:mars2020_mastcamz_sci_raw:data_imagedr:M20_MCZL_0001_0000700032_000RZL_N_01
                                                     │    │    │    │          │   │   │
                                                     │    │    │    │          │   │   └─ Version

                                                     │    │    │    │          └─────── RZL=Raw Zoom Left
```

## Cloud (AWS) — modern stack on a student credit budget

The stack can also be deployed combining self-managed compute with AWS
managed services, adopted selectively based on their real cost against a
limited student credit budget (ADR-011 to ADR-020 in the architecture
analysis):

```mermaid
flowchart TB
    subgraph EC2["EC2 — Airflow + Kafka self-managed"]
        A[Airflow]
        K[Kafka]
    end
    subgraph AWS["AWS Managed Services"]
        S3[(S3 — data lake)]
        RDS[(RDS PostgreSQL+PostGIS)]
        GLUE[Glue + Athena]
        LAMBDA[Lambda]
        SNS[SNS — alerts]
        CF[CloudFront + S3 — static demo]
    end
    A --> S3
    A --> RDS
    S3 --> GLUE
    S3 -- event --> LAMBDA
    A -. anomaly .-> SNS
    CF -. public landing .-> S3
```

MWAA (managed Airflow) and MSK (managed Kafka) were evaluated and
deliberately ruled out on cost grounds (~$300/month and ~$150/month
respectively) — the detail behind that decision is in ADR-014. The whole
deployment is provisioned with Terraform in [`infra/aws/`](infra/aws/README.md)
and documented step by step in Phase 4 of the implementation guide (ES).

## Not a technical reader? (recruiters / HR)

This project is a functional, end-to-end replica of the system NASA uses to
receive and process the Perseverance rover's photos and environmental data
on Mars — not a course exercise, but the simulation of a real data
engineering problem, built to the same standard (automated tests, cloud cost
control, decision documentation) a professional team would use. A 2-minute,
jargon-free explanation is in [section 10 of the implementation guide](docs/GUIA_IMPLEMENTACION_MODERN_DATA_STACK.md#10-explicación-para-perfiles-no-técnicos-cierre-de-la-guía) (in Spanish).

**What does the system do, in 6 steps?**

```mermaid
flowchart LR
    A["🤖 Rover on Mars<br/>Takes photos and<br/>measures weather<br/>(temp., wind, pressure)"]
    B["📡 Crosses space<br/>The signal travels<br/>3 to 22 minutes<br/>to reach Earth"]
    C["📥 Arrives and queues up<br/>Each piece of data<br/>waits in line<br/>to be processed"]
    D["🧹 Cleaned and validated<br/>Damaged data is discarded,<br/>readings are corrected<br/>with calibration data"]
    E["🚨 Checked for problems<br/>Automatically flags<br/>out-of-range readings,<br/>no manual review"]
    F["📊 Dashboard ready<br/>Charts and alerts<br/>for decision-making"]
    A --> B --> C --> D --> E --> F
```
